## Aggregator delta (so we can keep appending without bloating the main file)

***[Download 2aggreg_delta.md]*** — append-only "what changed" payload with hashes

This is the **incremental update mechanism**:

- Instead of rewriting the entire `concepts.json` every time a new term is added, the system appends changes to `2aggreg_delta.md`
- Each change includes a hash (for verification)
- Periodically, the deltas are "folded" into the main `concepts.json` file
- This is **exactly like Git** - small incremental commits that eventually merge into the main branch

## The Full Picture: Email as Concept Indexing System

Here's how it all connects:

### 1. **User sends/receives email** → Event creation
- Email subject + body + attachments
- TOFAR stamped with timestamp, sender, recipients, payload

### 2. **Email lands in Gmail** → Event storage
- Stored in Inbox/Sent/Drafts folders
- Indexed by Gmail's native search (sender, date, keywords)

### 3. **Concept harvester scans email** → Semantic extraction
- NLP pipeline extracts entities:
  - People: "Bill Murray", "Dale", "Catherine", "Mom"
  - Places: "Oklahoma", "Prague"
  - Domains: "AET engineering", "artemedics.com"
  - Concepts: "TED Talk", "JARVIS", "Seven Gates", "TOFAR"
- Adds new terms to `concept_harvest_terms.md`

### 4. **Terms promoted to concepts** → Graph update
- High-confidence terms become nodes in `concepts.json`
- Relationships inferred from co-occurrence
- Example: "Bill Murray" + "probe thread" → edge labeled "testing"

### 5. **User searches Gmail** → Semantic query
- Instead of searching "subject:Buddy", user searches:


  artemedics.com askcatgpt BillMurray CommunityRacksOfOklahoma

- System finds all emails that mention ANY of these concepts
- Returns 2 results: "Buddy Boot and Core PDF" + "Buddy Papers"

The Auto-Ingest Pattern for Concepts
Here's how auto-ingest works at the semantic layer:

Event: New email arrives
json
{
  "from": "daviddaniel.exet@gmail.com",
  "to": ["dglassesguy@gmail.com", "Bill Murray <bill@example.com>"],
  "subject": "Buddy TED and Prague Jarvis",
  "body": "An excellent question. Expressing this as Iron Man's JARVIS reveals several critical systems...",
  "attachments": ["docs.zip"]
}
Step 1: Tee to Harmonizer (NLP extraction)
json
{
  "topic": "core.harmonizer.in",
  "payload": {
    "text": "Buddy TED Prague JARVIS Iron Man critical systems",
    "entities": [
      {"text": "Buddy", "type": "SYSTEM"},
      {"text": "TED", "type": "EVENT"},
      {"text": "Prague", "type": "LOCATION"},
      {"text": "JARVIS", "type": "CONCEPT"},
      {"text": "Iron Man", "type": "REFERENCE"},
      {"text": "Bill Murray", "type": "PERSON"}
    ]
  }
}
Result: Harmonizer extracts 6 entities and adds them to concept_harvest_terms.md

Step 2: Tee to Dreamstream (Relationship inference)
json
{
  "topic": "core.dreamstream.in",
  "payload": {
    "edges": [
      {"from": "Buddy", "to": "TED", "type": "presentation_topic"},
      {"from": "TED", "to": "Prague", "type": "location"},
      {"from": "Buddy", "to": "JARVIS", "type": "inspired_by"},
      {"from": "Bill Murray", "to": "Buddy", "type": "collaborator"}
    ]
  }
}
Result: Dreamstream infers 4 relationships and updates concepts.json graph

Step 3: Unifier closes loop
json
{
  "topic": "unify.out",
  "parent": "email_123",
  "payload": {
    "ok": true,
    "concepts_added": 6,
    "edges_added": 4,
    "delta_hash": "a3f7c9e2..."
  }
}

**Result:** System confirms that the email has been successfully indexed. Future searches for "TED Prague JARVIS" will return this email.
